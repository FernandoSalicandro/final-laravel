✅ ORDINE CORRETTO DELLE MIGRAZIONI:
------------------------------------
1. 2025_11_04_183000_create_genres_table.php
   - Tabella: genres

   - Dipendenze: nessuna

2. 2025_11_04_183001_create_consoles_table.php
   - Tabella: consoles
   - Campi: id, name (nullable), timestamps
   - Dipendenze: nessuna

3. 2025_11_04_183001_5_create_games_table.php
   - Tabella: games
   - Campi: id, title, description, image_url, genre_id (FK), timestamps
   - Dipendenze: genres (foreign key genre_id → genres.id)
   - NOTA: Rinominato da "183001" a "183001_5" per garantire l'ordine corretto

4. 2025_11_04_183002_create_console_game_table.php
   - Tabella: console_game (PIVOT TABLE)
   - Campi: id, game_id (FK), console_id (FK), timestamps
   - Dipendenze: games e consoles
   - Relazione: Many-to-Many tra games e consoles

🔧 CONFIGURAZIONE DATABASE:
--------------------------
File: config/database.php
- Collation cambiata da 'utf8mb4_0900_ai_ci' a 'utf8mb4_unicode_ci'
- Motivo: Compatibilità con MySQL < 8.0 e MariaDB

================================================================================
                            2. MODELLI (Models)
================================================================================

✅ MODELLO: Genre.php
--------------------
Location: app/Models/Genre.php
Relazioni:
  - hasMany(Game::class) → Un genere ha molti giochi

✅ MODELLO: Game.php
-------------------
Location: app/Models/Game.php
Relazioni:
  - belongsTo(Genre::class) → Un gioco appartiene a un genere
  - belongsToMany(Console::class) → Un gioco può essere su molte console

✅ MODELLO: Console.php (CREATO DA ZERO)
---------------------------------------
Location: app/Models/Console.php
Relazioni:
  - belongsToMany(Game::class) → Una console ha molti giochi

SCHEMA RELAZIONALE:
------------------
Genre (1) ----< (N) Game (N) >----< (N) Console
              hasMany      belongsToMany

================================================================================
                      4. STORAGE E SYMLINK
================================================================================

🔗 SYMLINK CREATO:
-----------------
Comando eseguito: php artisan storage:link

Risultato:
  public/storage → storage/app/public

Questo permette di accedere ai file in storage/app/public tramite URL pubblici.

📁 STRUTTURA STORAGE:
--------------------
storage/
  app/
    public/
      games/
        farcry3.jpg ← Immagine del gioco caricata manualmente

🖼️ COME FUNZIONA:
----------------
1. File fisico: storage/app/public/games/farcry3.jpg
2. Nel DB: image_url = 'games/farcry3.jpg'
3. Nella view: <img src="{{ asset('storage/games/farcry3.jpg') }}">
4. URL pubblico: http://localhost/storage/games/farcry3.jpg

================================================================================
                      9. COMANDI UTILI
================================================================================

# Creare migration
php artisan make:migration create_table_name

# Creare model
php artisan make:model ModelName

# Creare seeder
php artisan make:seeder TableNameSeeder

# Eseguire migrazioni
php artisan migrate

# Resettare e rifare migrazioni + seeders
php artisan migrate:fresh --seed

# Creare symlink storage
php artisan storage:link

# Vedere stato migrazioni
php artisan migrate:status
